01 — Overview

The 4-Step Pipeline

Every match score you see in SkillBridge is the result of four sequential steps. This document explains each one in full detail.

1

📝 Text Normalization

Sanitizes text answers before grading identification questions.

2

📐 Feature Extraction

Converts student skill scores into a normalized numerical vector.

3

🎯 Cosine Similarity

Compares the student vector against each company position's requirement vector.

4

📊 TF-IDF Suggestion

Automatically tags assessment questions with the correct skill category.

02 — Technique 1

Text Normalization

🔤
Used in: Assessment Grading (Identification Questions)

How it works

Before comparing a student's text answer to the stored correct answer, both strings are normalized by stripping leading/trailing whitespace and converting to lowercase. This prevents false failures due to capitalization or spacing differences.

# api/scoring.py — score_submission() # For Identification question type: student_answer = response_answer.answer_text.strip().lower() correct_answer = answer_choice.choice_text.strip().lower() is_correct = (student_answer == correct_answer)

03 — Technique 2

Feature Extraction (Skill Vectors)

📐
Used in: Building Student Profile for Matching

How it works

After grading, each student's scores across all skill categories are converted into a numeric array called a Skill Vector. Each element corresponds to one skill category (e.g., ReactJS, Python, SQL). Scores are normalized from percentage (0–100) to a 0.0–1.0 scale. This transforms a qualitative skill profile into a format that a mathematical algorithm can work with.

# api/scoring.py — build_skill_vector(student, assessment, categories) categories = SkillCategory.objects.all().order_by('id') # categories = [ReactJS, Python, SQL, Networking] scores_map = {} # { category_id: percentage } for score in SkillScore.objects.filter(student=student, assessment=assessment): scores_map[score.skill_category_id] = score.percentage # Build the vector — one number per category, in consistent order vector = np.array([ scores_map.get(cat.id, 0.0) / 100.0 for cat in categories ], dtype=float) # Example result: # vector = [0.82, 0.60, 0.45, 0.30] # ReactJS Python SQL Networking

04 — Technique 3 (Core)

Cosine Similarity — The Matching Engine

🎯
Used in: Generating Company Recommendations

How it works

Cosine Similarity measures the angle between two vectors in multi-dimensional space. A score of 1.0 (100%) means the two vectors point in exactly the same direction — a perfect profile match. A score of 0.0 means no alignment at all. This is more powerful than simply comparing percentages because it evaluates the overall skill shape, rewarding students who are strong in the same areas the position demands.

# api/scoring.py — generate_recommendations() from sklearn.metrics.pairwise import cosine_similarity # For every student × every open position: score = cosine_similarity( student_vec.reshape(1, -1), # shape: (1, n_categories) position_vec.reshape(1, -1) # shape: (1, n_categories) )[0][0] match_score = score * 100 # convert 0–1 float to 0–100% # Classification thresholds: # match_score >= 80% → "Strong Match" 🟢 # match_score >= 60% → "Fair Match" 🟡 # match_score < 60% → "Low Match" 🔴
Cosine Similarity Formula
cos(θ) = (A · B) / (||A|| × ||B||)
where A = student skill vector  |  B = position requirement vector
A · B = dot product  |  ||A||, ||B|| = vector magnitudes

Worked Example — Step by Step

# Given: student_vec = [0.82, 0.60, 0.45, 0.30] position_vec = [0.90, 0.50, 0.70, 0.10] # Step 1: Dot product (A · B) dot = (0.82×0.90) + (0.60×0.50) + (0.45×0.70) + (0.30×0.10) = 0.738 + 0.300 + 0.315 + 0.030 = 1.383 # Step 2: Magnitude of student vector ||A|| ||A|| = sqrt(0.82² + 0.60² + 0.45² + 0.30²) = sqrt(0.6724 + 0.3600 + 0.2025 + 0.0900) = sqrt(1.3249) = 1.1510 # Step 3: Magnitude of position vector ||B|| ||B|| = sqrt(0.90² + 0.50² + 0.70² + 0.10²) = sqrt(0.8100 + 0.2500 + 0.4900 + 0.0100) = sqrt(1.5600) = 1.2490 # Step 4: Final cosine similarity cos(θ) = 1.383 / (1.1510 × 1.2490) = 1.383 / 1.4376 = 0.9620 match_score = 0.9620 × 100 = 96.2% → 🟢 Strong Match

05 — Technique 4

TF-IDF Category Suggestion

📊
Used in: Auto-tagging Assessment Questions

How it works

TF-IDF (Term Frequency–Inverse Document Frequency) is a classic NLP technique that measures how significant each word in a text is relative to a collection of documents. In SkillBridge, it's used to automatically suggest the most relevant skill category when an instructor writes a new question — making assessment creation faster and more consistent.

# api/scoring.py — suggest_category(question_text, categories) from sklearn.feature_extraction.text import TfidfVectorizer from sklearn.metrics.pairwise import cosine_similarity category_names = [cat.name for cat in categories] # e.g. ["ReactJS", "Python", "SQL Database", "Networking", "Computer Hardware"] # Combine category names + the new question into one corpus corpus = category_names + [question_text] vectorizer = TfidfVectorizer(stop_words='english') tfidf_matrix = vectorizer.fit_transform(corpus) # The question is the last row; categories are the first rows question_vec = tfidf_matrix[-1] category_vecs = tfidf_matrix[:-1] # Find the category with highest TF-IDF cosine similarity to the question similarities = cosine_similarity(question_vec, category_vecs)[0] best_idx = similarities.argmax() suggested_category = category_names[best_idx] # e.g. "SQL Database"

✅ Why Cosine Similarity is fair

Unlike raw percentage comparisons, cosine similarity is immune to scale differences. A student who scores 80% across all needed skills will match just as well as one who scored perfectly in some categories but missed others — what matters is the direction of the profile, not just the magnitude.

📋 Data quality dependency

The accuracy of recommendations depends directly on two things: (1) how accurately the assessment grading captures student skills, and (2) how accurately the company has set its position requirements. Both inputs are validated and entered by instructors and admin users respectively.

🔄 Re-runnable on demand

Recommendations can be re-generated at any time by the admin. This means if a company updates its position requirements or an instructor allows a student to retake the assessment, the match scores are recalculated fresh using the latest data.
